# نسخهٔ سه: پیاده‌سازی پژوهشی هفت مدل

شاخهٔ انتشار این نسخه `v3` و شاخهٔ توسعهٔ آن `v3-development` است؛ پایهٔ آن commit نسخهٔ دو با شناسهٔ `61097d772620e97fff7ec64a9f21b74a6eb9f913` است. شاخه‌های `main`، `v2` و `v2-development` حفظ می‌شوند. کدهای `v2/`، `v9/`، `vendor_v8/` و ورودی مستقل `run_v2.py` نیز تغییر نکرده‌اند. توسعه و مرج V3 فقط روی شاخه‌های نسخهٔ سه انجام می‌شود.

## اجرا

پس از نصب وابستگی‌های `requirements.txt`، دستور قبلی روی این شاخه V3 را اجرا می‌کند. مسیر خروجی جدید انتخاب کنید:

```bash
git fetch origin
git switch v3
```

```bash
python run_v9.py main --dataset ml-100k --data-root ./datasets --split-seeds 2026 --model-seeds 1 --k 20 --output ./results_v3/laptop_pilot
```

ورودی صریح و هم‌ارز آن `python run_v3.py ...` است. اجرای مستقل نسخهٔ دو همچنان با `python run_v2.py ...` انجام می‌شود. فایل `run_v9.py` فقط روی شاخهٔ V3 به ورودی جدید متصل شده است.

برای بررسی سریع مسیر اجرا:

```bash
python -m pytest -q tests
python run_v3.py main --dataset synthetic --quick --split-seeds 2026 --model-seeds 1 --k 4 --methods Method1,Method2,Method3,Method4,Method5,Method6,Method7 --v3-no-plots --output ./results_v3_smoke
```

`--quick` فقط آزمون اجراست: سه epoch، یک مرحلهٔ masked در هر epoch و کاهش بودجهٔ OOF، حل‌های عددی و آموزش توزیع. تمام سازوکارها فعال می‌مانند، اما این خروجی برای نتیجه‌گیری دربارهٔ کیفیت مدل مناسب نیست. اجرای کامل به‌صورت پیش‌فرض از پنج مرحلهٔ masked در هر epoch استفاده می‌کند؛ تعداد update، تعداد هدف‌های دیده‌شده و زمان در خروجی ثبت می‌شوند.

## تغییر واقعی هر مدل

| مدل | هویت حفظ‌شده | سازوکار نسخهٔ سه |
|---|---|---|
| M1 | AE و هندسهٔ شعاع/جهت | پیشنهاد در فضای مماس، فیلتر اطلاعاتی، حرکت روی کره، کنترل تعارض گرادیان بازسازی با پیش‌بینی |
| M2 | دو نمای کاربر و آیتم | آموزش جداگانهٔ خبرگی‌ها، سازگاری درون هر نما، gate بر پایهٔ residual خارج از fold و آستانهٔ عدم‌قطعیت مدل‌محور |
| M3 | شعاع اولیه و اصلاح نمایی | prior عصبی برای log-radius، گام Gauss–Newton مقید، CG بدون ماتریس متراکم و عدم‌قطعیت گرافی شرطی |
| M4 | prior شعاع محدود | انتقال prior به داخل بازه، دو ممان مثبت/منفی residual و projection روی چندضلعی دقیق ممان‌های مجاز |
| M5 | دو نمای encoder/decoder | میانگین decoder با ridge شرطی، تقریب گاوسی مشترک latent/decoder، تصحیح covariance در میانگین و کنترل اطمینان جهت‌دار |
| M6 | شعاع‌های واقعاً محدود | محدودسازی همهٔ شعاع‌ها، مرجع زاویه‌ای وابسته به context و spline یکنوا با قید میانگین و سقف شیب |
| M7 | مدل میانگین و عدم‌قطعیت | ensemble مستقل میانگین، اثر واقعی شعاع بر میانگین، توزیع ordinal منعطف با میانگین ثابت و تجزیهٔ دقیق واریانس mixture |

فرمول‌ها، فرض‌ها و مرز ادعاها در [V3_DESIGN.md](V3_DESIGN.md) آمده‌اند. این پیاده‌سازی به‌تنهایی اثبات ناولتی جهانی یا تضمین افزایش RMSE نیست.

## پروتکل داده و انتخاب مدل

train و test اصلی حفظ می‌شوند. validation اصلی به‌صورت قطعی و بدون استفاده از مقدار rating به سه نقش تقسیم می‌شود: ۶۰٪ انتخاب مدل/epoch، ۲۰٪ آموزش شکل توزیع M7 و ۲۰٪ توقف زودهنگام همان آموزش. هیچ pair مشترکی بین این سه نقش وجود ندارد؛ baselineها نیز همان بخش انتخاب ۶۰٪ را می‌بینند. نقش‌ها در `V3_ROLE_ASSIGNMENTS_<seed>.csv` و اطلاعات پروتکل در `V3_PROTOCOL_<seed>.json` ثبت می‌شوند. فایل split اصلی دست‌نخورده باقی می‌ماند.

بنابراین `val_RMSE` نسخهٔ سه روی جمعیت کوچک‌تری از validation تاریخی V2 محاسبه می‌شود. برای سنجش منصفانهٔ اثر معماری، V2 باید با نقش انتخاب، ظرفیت، تعداد update و بودجهٔ جست‌وجوی متناظر دوباره ارزیابی شود. یکسان بودن K به‌تنهایی به معنی یکسان بودن ظرفیت یا هزینه نیست؛ به‌ویژه برای ensemble مدل هفت و OOF مدل دو.

در آموزش masked، تمام نسخه‌های یک pair هدف از هر دو تاریخچه حذف می‌شوند. میانگین، واریانس، histogram، ویژگی‌های زمان، priorهای داده‌محور، covariance شرطی و مرجع زاویه‌ای از همان context ساخته می‌شوند. تأثیر معمول labelهای train بر پارامترهای آموزش‌دیده همچنان وجود دارد؛ این حذف ورودی با پیش‌بینی کاملاً OOF یکسان نیست. مدل دو برای gate واقعاً مدل‌های جداگانهٔ خارج از fold آموزش می‌دهد.

انتخاب hyperparameter در `scan` فقط با validation هر outer split انجام می‌شود. `final` سپس checkpoint منتخب را بازیابی و test را ارزیابی می‌کند. فرمان `main` نیز چند K را بر اساس validation انتخاب می‌کند، اما جایگزین جست‌وجوی کامل نیست. مرحلهٔ `calibration` معیار likelihood واقعی M7 را به‌طور جدا از مطالعهٔ اصلی RMSE انتخاب می‌کند.

پیش از refit نهایی، تنظیمات بایگانی‌شدهٔ scan، seedها، نسخهٔ سورس، دادهٔ train و نقش‌های validation دوباره کنترل می‌شوند. تغییر تنظیمات یا داده بعد از scan، اجرای نهایی را متوقف می‌کند و به scan تازه نیاز دارد. مسیر ترکیبی `all` نیز ذخیرهٔ predictionها و checkpoint منتخب را طبق تنظیمات مرحلهٔ نهایی فعال می‌کند؛ محدودیت ذخیره‌سازی scan به آن منتقل نمی‌شود.

## تنظیمات، خروجی و ادامهٔ کار

تنظیمات مستقل هفت مدل در `v3/config.py` تعریف شده‌اند و داخل config، fingerprint و checkpoint ذخیره می‌شوند. برای override از `--v3-config path/to/file.json` استفاده کنید؛ کلید نامعتبر رد می‌شود. نمونه:

```json
{
  "models": {
    "Method1": {"information_ridge": 1.0, "auxiliary_gradient_ratio": 0.3},
    "Method5": {"posterior_probes": 8, "posterior_cg_steps": 12},
    "Method7": {"ensemble_members": 3, "shape_epochs": 200}
  }
}
```

`--v3-max-epochs`، `--v3-steps-per-epoch`، `--v3-threads` و `--v3-no-plots` نیز در دسترس‌اند. گزینهٔ epoch فقط مدل‌های V3 را override می‌کند؛ baselineها تنظیمات مستقل قبلی خود را دارند. مدل چهار در حالت ممان دوطرفه به `K>=4` نیاز دارد تا کانال یک‌بعدیِ فاقد گرادیان زاویه‌ای ایجاد نشود.

checkpointهای V3 نسخهٔ معماری، تنظیمات، seed، تمام پارامترها/بافرها و hash دادهٔ train و نقش‌های validation را نگه می‌دارند. ذخیره اتمی و بازیابی strict است. archive پیش‌بینی‌ها در اجرای کامل، علاوه بر امتیازها، جزئیات سازوکار مدل و برای M7 احتمال‌ها و مؤلفه‌های واریانس را نیز ثبت می‌کند.

`--resume` مطالعه‌های **کامل‌شده** را با fingerprint یکسان رد می‌کند و از تکرارشان جلوگیری می‌کند. ادامهٔ optimizer از وسط یک epoch پیاده‌سازی نشده است؛ مطالعهٔ نیمه‌کاره را با مسیر خروجی تازه اجرا کنید. فایل‌های کش، checkpoint آزمایش، دیتاست و نتایج محلی جزو سورس تحویل و شاخه نیستند.

برای بررسی حفظ فایل‌های اصلی، `python verify_v3.py` را اجرا کنید. گزینهٔ `--require-uncommitted-base` فقط برای تحویل اولیهٔ بدون commit بوده است و بعد از انتشار V3 کاربرد ندارد. تنها تغییر تست تاریخی V2 این است که ورودی مستقل `run_v2.py` را کنترل می‌کند؛ تست جداگانهٔ V3 ورودی پیش‌فرض جدید را می‌سنجد. شواهد دیباگ و تست در `V3_VERIFICATION.json` ثبت شده‌اند.

fingerprint مطالعه و checkpoint، hash پیاده‌سازی V3 را نیز ثبت می‌کنند و از ادامهٔ آزمایش با سورس متفاوت جلوگیری می‌شود. کش، دیتاست و خروجی‌های آزمایش در commitهای V3 قرار نمی‌گیرند. بودجهٔ گام‌های اضافی Gauss–Newton مدل سه و تعداد هدف‌های استفاده‌شده در آن‌ها نیز جدا از updateهای Adam ثبت می‌شود.

## محدودیت‌های پژوهشی

- عدم‌قطعیت M2 آستانه‌ای مدل‌محور است و تضمین distribution-free ندارد؛ OOF و refit نهایی نیز اندازهٔ context یکسان ندارند.
- M3 و M5 به خطی‌سازی، prior و تعداد probe/CG حساس‌اند. M5 وزن‌های شبکهٔ encoder را شرط می‌کند و کل posterior شبکه را انتگرال نمی‌گیرد.
- قیود M4 امکان‌پذیری ممان‌ها را تضمین می‌کنند، نه کاهش قطعی خطای پیش‌بینی.
- قید میانگین M6 دربارهٔ قانون مرجع زاویه‌ای تعریف‌شده است. مرجع تجربی تخمینی است؛ برای هر کاربر یا هر نمونهٔ test تضمین calibration ایجاد نمی‌کند.
- برای ratingهای پیوسته، M7 توزیع متفاوتِ mixture بتا با میانگین مشترک دارد. NLL آن با clipping صریح نقاط انتهایی گزارش می‌شود و با NLL ordinal قابل‌مقایسهٔ مستقیم نیست.
- تست‌ها و smoke در CPU بررسی شده‌اند. برای نتیجهٔ علمی باید اجرای کامل با چند split/seed، ablation و بررسی هزینه انجام شود؛ برتری تجربی V3 نسبت به V2 هنوز ثابت نشده است.
